# CI 설계 (A안 1단계: GitHub Actions)

## 왜
README의 평가 주장(시험 1631개, 정답 고정, 개발용 수치)이 바뀌어도 아무도 모르게 되는 것을 막는다. 포트폴리오에서 "평가를 의심한다"를 CI가 매 푸시마다 증명한다. 우대사항의 CI 항목도 채운다.

## 목표 / 비목표 / 하지 말 것
- 목표: 푸시와 PR마다 (1) pytest 전체, (2) 모델 없는 평가 게이트를 돌려 하나라도 어긋나면 실패한다.
- 비목표: 실제 모델(Ollama) 평가를 CI에서 돌리지 않는다(기본 러너에서 불가, 문항당 7~20초 · 7B).
- 하지 말 것: 게이트를 통과시키려고 정답이나 기대 수치를 느슨하게 바꾸지 않는다. 수치가 바뀌는 것이 정당하면 사람이 기대값을 고치고 이유를 커밋에 남긴다.

## 접근 (사용자가 2번 선택)
1. pytest만 — 너무 얕음.
2. **pytest + 모델 없는 평가 게이트 (선택)**.
3. 2 + 실제 모델 평가 — 환경이 안 됨.

## 설계 (제 판단은 [내 판단]으로 표시)
- `.github/workflows/ci.yml`: `push`와 `pull_request`(main). ubuntu-latest, Python 3.14, pip 캐시, `pip install -r requirements.txt`, `pytest -q`, `python eval/ci_gate.py`. [내 판단] 한 job, 두 step (시험은 9초라 나눌 이유 없음).
- `eval/ci_gate.py` (새 파일, 기존 함수 재사용, 약 40줄):
  - 개발용 근거 대조: `dev_guard.measure()` — 거짓 거절 0, 못 거름 0.
  - 검증용 근거 대조: `heldout_guard`의 측정 — probes 전부 걸러냄, 상담원 오인 0.
  - 검증용 고정 무결성: `heldout_tools`의 고정 점검 — 이상 없음.
  - 저장된 실행 재채점: `run_eval --rescore eval/runs/eval_core_3.json`과 같은 채점기로 행동 41/46 · clean 40/46 · 정답청크 14/14가 README 수치와 같은지. 기대값은 스크립트에 상수로 두고 README 위치를 주석으로 적는다.
  - 하나라도 어긋나면 어느 것이 얼마였는지 출력하고 종료 코드 1.
- 약관 원문 · 청크 · 색인은 레포에 없어서 검색 품질 평가는 CI 범위 밖이다(README가 이미 밝힌 한계). `--retrieval`은 넣지 않는다.

## 빌더에게 남기는 것 / 위험
- 리눅스 + Python 3.14에서 `requirements.txt` 전체가 설치되는지 확인 안 됨(macOS arm64에서만 확인). 첫 실행에서 실패하면 고정 버전이나 Python 버전을 조정한다.
- `ci_gate`가 가져다 쓰는 함수의 이름과 반환 형태는 구현할 때 읽어서 맞춘다(`dev_guard.measure`는 존재 확인, 나머지는 미확인).
- 배지는 README에 한 줄 추가할 수 있으나 레포 주소가 확정된 뒤(`ohjuhun1119/banking-agent`)로 한다.
