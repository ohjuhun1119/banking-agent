# 약관 조항 대조 설계 (A안 2단계: 런타임 가드 + 채점)

## 왜
지금은 검색된 조항을 카드로 붙일 뿐, 모델이 검색 결과를 잘못 요약해도(예: 금리 0.15%를 0.25%로, 일부해지 2회를 3회로) 막지 못한다(DEVLOG 665줄, README가 인정한 한계). 이 한계를 코드로 줄이고, 줄었는지 숫자로 보인다.

## 목표 / 비목표 / 하지 말 것
- 목표: 답변에 나온 **퍼센트 · 기간 · 횟수**가 사용자 말, 도구 결과(검색된 조항 본문, 계산·구간 조회 결과)에 없으면 막는다. 같은 검사를 평가 채점에도 쓴다.
- 비목표: 문장의 의미(`일부해지는 안 된다` 같은 주장)까지 판정하지 않는다. LLM 판정은 7B로 신뢰하기 어렵고 CI에서 못 돌려 제외한다. 날짜 · 금액은 `ungrounded_values`가 이미 본다.
- 하지 말 것: 통과율을 올리려고 점검을 느슨하게 하지 않는다. 거짓 거절(맞는 답을 막음)은 측정해서 보고한다.

## 접근 (사용자가 큰 방향 선택: 런타임 가드 + 채점)
- 가드만 / 채점만: 둘 다 필요해서 제외(사용자 선택).
- **[내 판단] 값 단위 정확 일치**: 답변의 퍼센트 · 기간 · 횟수를 뽑아 허용된 글에서 뽑은 값과 같은지 본다(`0.20%`와 `0.2%`는 같은 값으로). 결정적이고 모델 없이 돌아 CI에 맞다.
- 문장 단위 겹침(n-gram) 대조: 바꿔 쓴 올바른 답을 막는 거짓 거절이 많을 것 같아 제외.

## 설계
- `app/answer_check.py`에 `ungrounded_terms(answer, allowed_texts) -> list[str]`: 퍼센트(`\d+(\.\d+)?\s?%`), 기간(`\d+\s?(개월|일|년|영업일)`), 횟수(`\d+\s?회`)를 값으로 정규화해 비교, 허용 글에 없는 값을 `0.25%` 형태로 돌려준다. 허용 글은 `ungrounded_values`와 같은 `_allowed_texts(state, whole_conversation=True)`를 재사용한다.
- `app/graph.py`의 `check_reply`에 새 문제 `terms`를 `ungrounded` 다음에 추가한다. 걸리면 기존 흐름대로 한 번 다시 시키고, 또 걸리면 고정 문구로 나간다. 다시 시키는 문장은 기존 `ungrounded` 항목과 같은 방식으로 적는다.
- 채점: `eval/evaluate.py`의 근거 없는 답변 표시가 가드와 같은 함수를 쓰게 해, 가드가 막는 것과 채점이 표시하는 것이 어긋나지 않게 한다(기존 `heldout_run.grade`와 같은 방식).
- 시험: 약관 본문이 레포에 없으므로 짧은 **가짜 조항**(예: `중도해지 이율은 가입 3개월 이상 6개월 미만 연 0.20%`)을 시험 안에 둔다. 통과(조항에 있는 값), 막힘(없는 값), 사용자가 말한 값 허용, `0.20%`/`0.2%`·`3 개월`/`3개월` 정규화, 그래프에서 다시 시킴 → 고정 문구 경로, 가드를 끄면 시험이 실패하는지(변형 시험)를 둔다.
- 측정: 기록된 실제 모델 답변(`tests/test_heldout.py`의 녹화 자료와 `eval/runs`)에 새 검사를 돌려 거짓 거절을 센다. 이 수치와 한계를 README에 쓴다.

## 빌더에게 남기는 것 / 위험
- 거짓 거절: 계산 결과에서 파생된 값(예: `경과 3개월`)이나 약관 밖 일반 설명의 숫자를 막을 수 있다. 막혀도 안전한 쪽(다시 시킴 → 고정 문구)이지만 얼마나 자주인지는 **아직 모른다**. 측정 전에는 기본 켜짐으로 둘지 정하지 않는다: 거짓 거절이 크면 표시만 하는 모드로 낮추고 이유를 기록한다.
- `eval/runs`의 답변은 앞 300자만 저장돼 있어 전체 재측정은 못 한다. 녹화 자료에 허용 글이 함께 있는지는 구현할 때 확인한다.
- 이 검사는 숫자만 본다는 한계를 README에 그대로 적는다.
