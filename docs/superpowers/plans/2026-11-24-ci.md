# CI (pytest + 평가 게이트) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** push와 PR마다 pytest 전체와 모델 없는 평가 게이트를 GitHub Actions에서 돌려, 평가 수치가 README와 어긋나면 실패하게 한다.

**Architecture:** `eval/ci_gate.py`가 기존 평가 함수(`dev_guard.measure`, `heldout_guard.measure`, `heldout_tools.verify`, `run_eval.rescore` + `evaluate.summarize`)를 불러 기대값과 비교하고, 어긋난 항목 목록을 출력한 뒤 종료 코드를 돌려준다. 워크플로는 그것과 pytest를 한 job에서 차례로 실행한다.

**Tech Stack:** Python 3.14, pytest 9.1.1, GitHub Actions (`actions/checkout`, `actions/setup-python` + pip 캐시).

**Spec:** `docs/superpowers/specs/2026-11-24-ci-design.md`

## Global Constraints

- 실제 모델(Ollama)과 약관 원문 · 청크 · 색인은 CI에 없다. 게이트는 이것 없이 돌아야 한다.
- 기대 수치를 느슨하게 바꿔 게이트를 통과시키지 않는다. 바꿀 때는 이유를 커밋 메시지에 쓴다.
- 기대값은 README 수치와 같아야 한다: 행동 41/46, 깨끗한 답변 40/46, 정답 청크 14/14 (`eval/runs/eval_core_3.json`, 2026-11-04).
- 커밋 메시지 끝에 `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`를 붙인다.
- 새 의존성을 추가하지 않는다.

## Review Focus

- `eval/runs/eval_core_3.json`의 문항 글이 현재 문항 파일과 달라 재채점에서 건너뛴 줄이 생기는 경우: 건너뜀이 하나라도 있으면 실패해야 한다(조용히 분모가 줄면 안 된다).
- 검증용 `probes`가 비는 경우(문항 id 변경으로 전부 건너뜀): 0개를 통과로 보면 안 되므로 `probes` 개수가 12인지도 확인한다.
- 정답 고정 파일이 없는 경우(`verify`가 "고정되지 않았습니다"를 돌려줌): 실패여야 한다.
- 게이트 하나가 예외를 던지는 경우: 나머지 게이트 결과를 가리지 않고 실패로 보고해야 한다.
- 출력에 약관 본문이 길게 실리지 않아야 한다(어긋난 값의 id와 수치만).

### Task 1: 평가 게이트 `eval/ci_gate.py`

**Files:**
- Create: `eval/ci_gate.py`
- Test: `tests/test_ci_gate.py`

**Interfaces:**
- Consumes: `dev_guard.measure() -> dict` (키 `false_rejections`, `missed`), `heldout_guard.measure() -> dict` (키 `probes`, `probes_not_caught`, `handoff_false_positives`), `heldout_tools.verify() -> list[str]`(빈 목록이면 이상 없음), `run_eval.rescore(path, questions) -> (rows, {"skipped": [...], ...})` with `run_eval.load()`, `evaluate.summarize(rows)["overall"]` (각 지표는 `{"hit": int, "n": int}`).
- Produces: `check_all(runs_path: str = "eval/runs/eval_core_3.json") -> list[str]` (어긋난 항목 설명, 빈 목록이면 통과), `main(argv=None) -> int` (실패가 있으면 1). 상수 `EXPECTED = {"behavior_ok": (41, 46), "clean": (40, 46), "gold_chunk_in_evidence": (14, 14)}`와 `EXPECTED_PROBES = 12`.

- [ ] **Step 1: Write the failing tests** in `tests/test_ci_gate.py`:
  - `test_the_real_repo_passes_every_gate`: `check_all() == []`.
  - `test_a_score_below_the_expected_value_is_reported`: `check_all`에 기대값을 monkeypatch로 `{"behavior_ok": (42, 46)}`로 바꾸면 결과 목록이 비지 않고 `behavior_ok`와 `41`과 `42`를 포함한다.
  - `test_skipped_rows_in_the_saved_run_fail_the_gate`: 문항 글을 바꾼 임시 복사본(`tmp_path`에 저장 파일을 복사해 첫 줄의 `question`을 바꿈)을 경로로 주면 `skipped`를 언급하는 항목이 나온다.
  - `test_a_missing_freeze_manifest_fails`: `heldout_tools.verify`를 `lambda: ["고정되지 않았습니다 ..."]`로 monkeypatch하면 결과에 그 문구가 들어 있다.
  - `test_one_gate_raising_does_not_hide_the_others`: `dev_guard.measure`가 예외를 던지게 monkeypatch해도 `check_all`이 예외 없이 돌아오고, 결과에 `dev_guard`를 언급하는 항목이 있다.
  - `test_main_returns_1_on_failure_and_0_on_success`: 위 monkeypatch 유무에 따라 `main([])`가 1과 0.
- [ ] **Step 2: Run to verify they fail**
  Run: `.venv/bin/python -m pytest tests/test_ci_gate.py -q`
  Expected: FAIL (`eval.ci_gate` 없음).
- [ ] **Step 3: Implement `check_all` and `main` in `eval/ci_gate.py`.** 각 게이트를 `try/except Exception`으로 감싸 실패 항목에 게이트 이름을 붙인다. 개발용: `false_rejections`와 `missed`가 0. 검증용: `len(probes) == EXPECTED_PROBES`, `probes_not_caught`와 `handoff_false_positives`가 비어 있음. 고정: `verify()`가 빈 목록. 재채점: `skipped`가 비어 있고 각 지표 `hit`, `n`이 `EXPECTED`와 같다. `eval/` 모듈 import는 기존 파일들처럼 `sys.path.insert`로 한다. 출력은 항목당 한 줄(id와 수치만).
- [ ] **Step 4: Run to verify they pass**
  Run: `.venv/bin/python -m pytest tests/test_ci_gate.py -q && .venv/bin/python eval/ci_gate.py; echo $?`
  Expected: 시험 통과, 게이트 출력 없음 또는 `OK` 한 줄, 종료 코드 0.
- [ ] **Step 5: Run the whole suite**
  Run: `.venv/bin/python -m pytest -q`
  Expected: `1637 passed` 안팎(기존 1631 + 새 시험 6), 실패 0.
- [ ] **Step 6: Commit** `eval/ci_gate.py`, `tests/test_ci_gate.py` — `feat: model-free evaluation gate for CI (guards, freeze check, saved-run rescore)`
